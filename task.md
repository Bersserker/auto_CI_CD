# Итоговый проект по дисциплине «Автоматизация процессов доставки и развертывания моделей машинного обучения»

## Название проекта

**Промышленное развертывание кредитной скоринговой системы с полным MLOps-циклом.**

## Контекст и цель

Кредитный скоринговый проект из курса «Автоматизация процессов разработки и тестирования моделей машинного обучения» одобрен руководством банка для промышленного внедрения. Необходимо создать отказоустойчивую масштабируемую систему с автоматизированной доставкой моделей и комплексным мониторингом.

Основа работы — существующий репозиторий модели оценки вероятности дефолта клиента (PD-модели). Необходимо развить имеющиеся процессы подготовки данных, обучения, тестирования, версионирования и API до полного промышленного MLOps-цикла.

**Объём работ:** выполняются все задания, включая все пункты, обозначенные в исходном задании как опциональные. Далее они включены в общий обязательный чек-лист. Возможность выбора между альтернативами (например, quantization или pruning, ELK или Loki) сохраняется.

Статусы ниже отражают план работ; наличие реализации и её соответствие требованиям необходимо проверить отдельно перед отметкой выполнения.

## Этап 1. Подготовка модели к промышленной эксплуатации

### 1.1. Нейронная сеть и конвертация в ONNX

- [ ] Создать и обучить новую нейронную сеть для кредитного скоринга; архитектуру выбрать и обосновать.
- [ ] Конвертировать NN-модель в формат ONNX.
- [ ] Написать скрипт валидации корректности конвертации: проверить входы и выходы, сравнить предсказания на одинаковых данных, зафиксировать допустимую численную погрешность.
- [ ] Сравнить производительность инференса исходной NN-модели и ONNX-версии на CPU.

### 1.2. Оптимизация модели

- [ ] Применить quantization для уменьшения размера модели или pruning для ускорения инференса.
- [ ] Измерить и сравнить качество, размер артефакта и производительность до и после оптимизации.
- [ ] Зафиксировать параметры оптимизации и вывод о пригодности оптимизированной модели для эксплуатации.

### 1.3. Производительность

- [ ] Провести нагрузочное тестирование модели на CPU- и GPU-инстансах.
- [ ] Сравнить конфигурации ресурсов и определить оптимальную для production.
- [ ] Подготовить отчёт с benchmark-тестами: оборудование, версии ПО, параметры нагрузки, latency, throughput, потребление ресурсов и результаты сравнения.

**Результат этапа:** обученная NN-модель, ONNX-артефакт, оптимизированная версия, скрипты валидации и измерений, отчёт о качестве и производительности.

## Этап 2. Cloud Infrastructure as Code

### 2.1. Terraform-конфигурация

- [ ] Выбрать облачную платформу из предложенных: Yandex Cloud, VK Cloud, Selectel или Beget; обосновать выбор.
- [ ] Создать Terraform-конфигурацию для развертывания инфраструктуры в выбранном облаке.
- [ ] Реализовать отдельные модули VPC/network, Kubernetes, Storage и Monitoring.
- [ ] Разделить конфигурации окружений staging и production.
- [ ] Настроить remote state в Object Storage с раздельным состоянием окружений.

Пример структуры из задания:

```text
infrastructure/
├── modules/
│   ├── network/
│   ├── kubernetes/
│   ├── storage/
│   └── monitoring/
├── environments/
│   ├── staging/
│   └── production/
└── scripts/
```

### 2.2. Kubernetes-кластер

- [ ] Автоматизировать создание Managed Kubernetes-кластера.
- [ ] Настроить node groups с CPU- и GPU-инстансами.
- [ ] Настроить сетевые политики Kubernetes и security groups облачной инфраструктуры.
- [ ] Проверить воспроизводимость развертывания и документировать необходимые параметры и команды.

**Результат этапа:** модульная Terraform-конфигурация, remote state, окружения staging/production и работающий Managed Kubernetes с CPU/GPU node groups.

## Этап 3. Контейнеризация и оркестрация

### 3.1. Оптимизация Docker-образов

- [x] Реализовать отдельные образы для frontend и backend.
- [x] Интегрировать DVC в Docker-образ для управления версиями данных и получения нужных артефактов.
- [x] Проверить сборку и запуск образов, документировать их назначение и конфигурацию.

### 3.2. Kubernetes-манифесты

- [x] Реализовать Deployment со стратегией rolling update.
- [x] Настроить ConfigMaps и Secrets для управления конфигурацией.
- [x] Создать Service и Ingress для доступа к API.
- [x] Проверить развертывание компонентов и доступность API в Kubernetes.

**Результат этапа:** отдельные образы frontend/backend, многостадийные Dockerfile и Kubernetes-манифесты с управляемой конфигурацией и доступом к API.

Команды и ограничения описаны в `infrastructure/kubernetes/README.txt`, результаты — в `infrastructure/kubernetes/verification.txt`. Облачное развёртывание с настоящей моделью ожидает аккаунта и артефакта.

## Этап 4. Дополненный CI/CD-пайплайн

### 4.1. GitHub Actions

- [ ] Расширить GitHub Actions до multi-stage pipeline: `build → test → deploy → monitor`.
- [ ] Добавить security scanning и vulnerability checking.
- [ ] Настроить автоматическое развертывание в staging и production.
- [ ] Реализовать проверки работоспособности и мониторинг после развертывания.

Пример структуры из задания:

```text

├── build-and-test.yml
├── deploy-staging.yml
├── deploy-production.yml
```

### 4.2. Стратегии развертывания

- [ ] Реализовать Blue-Green-развертывание с использованием Istio.

- [ ] Определить критерии успешного релиза и условия остановки продвижения версии.
- [ ] Создать механизм автоматического rollback при проблемах.
- [ ] Продемонстрировать переключение версий и откат при нарушении заданных критериев.

**Результат этапа:** работающий CI/CD для обоих окружений, проверки безопасности, Blue-Green и Canary, автоматический rollback.

**Результат этапа:** сбор метрик и логов, дашборды, работающие алерты и runbook.

- [ ] Зафиксировать эталонные данные, окна наблюдения и пороги срабатывания.

- [ ] Настроить shadow deployment для тестирования новых моделей.
- [ ] Документировать распределение трафика, сбор результатов и критерии сравнения версий.

**Результат этапа:** мониторинг дрифта и ухудшения качества, дашборды, Seldon Core, A/B-тестирование и shadow deployment.
